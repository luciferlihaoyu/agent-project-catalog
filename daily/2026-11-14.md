## 最值得关注的 3 个仓库

### 1. tailscale/tailcat — 剥掉控制面的 netcat，把"网络工具"打回协议原形
+256 是今天全场最高增速，而且来自 Tailscale 官方。netcat 五十年来的用法都是"TCP/UDP 之上互相丢字节"，tailcat 把传输层换成 WireGuard 数据面报文：没有控制面、没有账号、没有 NAT 穿透协调，两个知道对方节点公钥的机器直接互换流量。它的锋利之处在于把 Tailscale 拆开了——平时大家用的是"控制面+数据面"捆绑的全家桶，tailcat 证明数据面本身就能当通用网络工具用。9,457 星 / 仅 42 issues / fork 率 4.6%，健康度是今天 7 个仓库里最好的；唯一要留意的是最后推送停在 2026-11-05，且功能矩阵（reconnect/多路复用）还在铺。做内网调试、点对点管道的人值得直接上手。

### 2. backnotprop/plannotator — agent 工作流的"批注层"，人重新拿回决定权
一年不到 10,451 星，今天 +108 还在稳态增长。它的定位在 agent 工具链里很独特：不是又一个 harness、不是又一个 IDE，而是横在"agent 提方案"和"agent 执行"之间的批注工作台——shape、decide、plan、annotate、review，最后一键把所有反馈发回给 agent。Topics 里 claude-code/codex/opencode/pi-mono 全都在，说明它做的是跨 harness 的通用层，这与本 catalog 里 JetBrains thinkrail（给 pi 套 IDE）、paperclip（团队级 agent 管理台）形成互补：thinkrail 管运行时宿主，plannotator 管人在环的决策界面。208 open issues 对 1 万星来说很干净，Apache-2.0 + 官网 plannotator.ai，商业公司的做派。做 agent 工作流的人应该把它和 plan-mode 一起评估。

### 3. ChromeDevTools/chrome-devtools-mcp — 浏览器调试的官方 MCP 标准，agent 时代的 DevTools
Chrome 官方出品，55,452 星、116 open issues、最后推送前一天——这是今天清单里"体量 × 维护健康度"最夸张的组合。它把 DevTools 协议包成 MCP server，让 coding agent 直接拿到性能 trace、网络检查、console、page snapshot 这类"浏览器侧的真相"，而不是靠截屏猜。对比已收录的 vercel-labs/agent-browser（Rust CLI 直调路线）和 lightpanda/browser（自研引擎）：chrome-devtools-mcp 是官方把"给 agent 用"变成了 DevTools 的一等公民场景，等于给整条 agent-browser 赛道发了标准。做浏览器自动化、E2E、agent 调试的工具链，接它比自研协议层划算。
