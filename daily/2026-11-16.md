## 最值得关注的 3 个仓库

### 1. NVIDIA/SkillEvaluator —— Skills 生态终于有了「质检员」
今天这批 4 个仓库里最结构性的一件：三家（Google、NVIDIA、社区）同时上 Trending，说明 Skills 已经从「生产」进入「治理」阶段。SkillEvaluator 提供的是多层质量闸门：语义重叠检测（解决 82 个 skill 里 40 个在干同一件事的 duplication 灾难）、合成评测数据集生成、以及最关键的 **live agent evaluation**——真正测量某个 skill 装上后 agent 行为变了多少，而不是看作者自吹的 benchmark。搭配已收录的 NVIDIA/SkillSpector（安装前扫漏洞），NVIDIA 手里已经是一套「扫安全 + 评质量」的双闸。1,680 星仍处早期，值得现在跟进。

### 2. elementalsouls/Claude-BugHunter —— 进攻性 security skill 的工业化样本
82 个 skills + 15 个 slash commands + **681 份已披露报告的模式提炼**，覆盖 24 类核心漏洞，另附企业身份与基础设施攻击矩阵。它和已收录的 Claude-Red（78 skills / 23 类攻击面）是同赛道的正面对手，但差异点在「681 份真实报告」这个语料厚度——把公开 HackerOne/Bugcrowd 报告里的真实 payload 与绕过手法固化进 skill。fork 率 15.0% 且仅 6 open issues，说明是「拿来就改」而非「收藏吃灰」。⚠️ MIT 协议但工具性质敏感，仅限合法授权测试。

### 3. google-labs-code/stitch-skills —— Google 把「设计转代码」钉在 MCP 上
Stitch 是 Google 的 UI 设计工具，这个仓库把 skills 绑死到 Stitch 的 MCP server 上，并明确声明遵循 Agent Skills 开放标准以兼容 Antigravity / Gemini CLI / Claude Code / Cursor。战略含义比代码本身重要：Google 在用「开放标准 + 自家 MCP 服务」的组合抢 agent 设计工作流的入口层，与 google/skills、android/skills 形成三件套。⚠️ 但**最后推送停在 2026-08-17**，已三个月没动，今日 +247 纯属榜单惯性，跟进前先确认 Stitch MCP 是否还在迭代。

## 趋势观察

- **Skills 从「写」转向「管」**：今天 4 个新仓库有 3 个是 skill 本身或其治理工具（stitch-skills、Claude-BugHunter、SkillEvaluator）。当 anthropics/skills 已达 18.9 万星，真正的痛点不再是「没有 skill」，而是「skill 太多、互相重叠、不知道哪个真有用」。评价、扫描、去重、评测数据集正在成为新的基础设施层。
- **厂商把 MCP 当护城河入口**：Google Stitch、NVIDIA SkillEvaluator 都在做同一件事——把自己的服务做成 MCP server，再用官方 skills 收集略把 agent 导流回来。开放标准是表象，服务绑定是实质。
- **ggml 本体单独上榜是个信号**：长期只作为 llama.cpp 的「隐形依赖」，ggml 作为独立张量库拿到 15,907 星 + 386 issues，说明有人开始绕过 llama.cpp 直接在 ggml 上做自己的推理栈（TensorFold、colibri 那批 Zig/C 新秀走的就是这条路）。底层正在被重新分层。
