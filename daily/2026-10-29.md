### 🥇 ruvnet/RuView —— 10 万星不是噱头，是「WiFi 当传感器」这条路线跑通了

**⭐ 101,055 / 🍴 13,161（fork 率 13.0%）/ MIT / +557**。10 万星的项目不少，但**同时有 1.3 万 fork、每天还在 +557、并且有真实硬件在跑**的极少。看点有三层：

1. **它把「感知」从摄像头彻底移到了射频层**。ESP32 + Realtek RAC1 抓 CSI，透墙测人在不在、几个人、呼吸率心率、跌倒、睡眠分期 —— **没有一帧视频**。这一条不只是隐私卖点，更是**成本与部署量级的碾压**：一个 ESP32 节点几十块钱，摄像头方案要算上带宽、存储、GPU 推理和布线的边际成本。**10 万星说明市场要的是这个方向，不是「又一个小智」**。
2. **它没有停在「能演示」，而是铺到了生态位上**：Home Assistant 一个 `--mqtt` 标志、21 个实体（11 原始 + 10 推断语义，含 elderly-inactivity-anomaly、fall-risk-elevated、bed-exit 这类**照护场景**）、3 个 Blueprint；再往上是 Matter Bridge 打通 Apple Home / Google Home / Alexa / SmartThings。**「能接进别人家的智能家居」比「自己能跑」难一个数量级**——这是硬件项目能不能活过第一年的分水岭。
3. **它给 agent 配了「不许吹牛」的护栏**。MetaHarness 提供 MCP server、Claude Code mod、受限 Codex agent、确定性 `verify`，还有一个 `claim-check --file REPORT.md` 对报告里的准确性声明做**诚实性检查**；agent run 默认**只读**，写工作区要 `--allow-write` + `--confirm`，硬件读要 `device-access` 授权，**刷固件和校准永远不走 HTTP 传输**。README 自己写「accuracy is still synthetic until real-data validation」、设备体征标注低置信 —— **在一个全是吹牛的项目里，一个主动交代边界的项目反而更可信**。

⚠️ 关注理由：**① 精度是最大变量** —— README 自己承认合成数据上的准确率不等于真实环境，这是整个 WiFi sensing 赛道的原罪，需要看真实住宅的长跑数据；**② 504 个 open issues** 对 10 万星只有 0.5%，比例健康，但绝对量意味着边缘情况（多人、隔墙、多径）极多；**③ 硬件门槛甩不掉** —— 消费级路由器 CSI 质量参差，好效果依赖特定网卡/节点，环境敏感度决定它是「实验室神器」还是「家庭真能用的东西」；**④ 项目面过宽**（python/ + firmware/ + harness/ + dashboard/ + ui/ + v2/ + aether-arena/ + wifi-veil/ 多套并行），有明显的**概念先行、收敛未完成**的味道；**⑤ 与隐私法规的张力**——「不用摄像头」是卖点，但**无感知存在/呼吸/心率检测本身就是更高敏感度的数据**，责任边界比摄像头更模糊。

## 🔭 简短趋势观察

1. **「平台方亲自下场教 agent」是今天最被低估的信号。** expo/skills 是**第一个由框架/平台官方发布的 agent skill 集合** —— 此前 skill 生态的主力是社区整理（AWS、Cloudflare、NVIDIA），今天出现了「Expo 官方账号 + 官方徽章 + 官方插件市场分发」的形态。**平台方承认 agent 是一等调用方，并开始为 agent 单独写教材、单独做更新通道、单独标注付费边界**。配合它写下的那句「Expo 文档与 CLI 仍是 source of truth」——**生态正在形成「文档给机器读、skill 给 agent 用」的双层结构**，而不是让 skill 取代文档。这个模型一旦成立，会成为所有 SDK/框架的标准动作。

2. **「不用摄像头」正在成为一种技术路线，而不只是隐私话术。** RuView 用 ESP32 抓 CSI 做透墙存在检测/呼吸/心率/跌倒，10 万星 + 1.3 万 fork + 已接入 Home Assistant / Apple Home / Alexa。**关键不是它多准，而是它把「感知」的边际成本从「摄像头+带宽+GPU+布线」压到了「一个几十块的 ESP32」**。更值得注意的是它给 agent 配的护栏：默认只读、写操作要双重确认、刷固件不走 HTTP、`claim-check` 检查报告里的夸大声明、README 自承合成数据精度不等于真实精度。**在一个满是吹牛的赛道里，一个主动交代边界的项目反而更容易拿到信任和生态位。**

3. **「缝合工具」和「重造工作台」是同一枚硬币的两面。** macro 的立论很直接：用 Slack + Linear + Notion + HubSpot + Superhuman 的公司「不是可计算的，公司是被 MCP 和 Zapier 缝起来的」——**所以它用 Rust + SolidJS 从地基重写，把跨引用存成双向图谱，让 agents 共享团队级记忆**。而 DeepTutor、hallmark、superpowers 这些已归档项目走的是另一条路：不重造，让现有软件变 agent-native。**两条路都在 Trending 上同一天出现，说明「工具该被 agent 吃掉还是该被 agent 重造」这个问题还没有定论** —— 但无论走哪条，共同前提都是一样的：**人不该再坐在工具之间来回切换了**。
