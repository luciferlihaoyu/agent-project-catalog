## 最值得关注的 3 个仓库

### 1. ashhart/TensorFold — 用 Zig 重写 LLM 推理，赌的是"一个引擎跑三种 GPU"
5 个月 1,938 星，今天的增速并不惊人（+54），但它的定位在整条 Trending 里最锋利：Metal、CUDA、Vulkan 三套后端共用一套推理内核。过去这是 llama.cpp 的主场（Metal/Vulkan 靠 ggml 后端、CUDA 自己一套），TensorFold 等于直接对着 llama.cpp 的护城河下手，而且选了 Zig——没有 CMake 生态包袱、编译期泛型写内核特别顺手。**fork 率 20.2% 是这批里最高的**，说明看的人不只是收藏，是真在自己机器上编译试跑。警示也很实在：522 open issues（远超 1,938 星的体量），硬件矩阵还没铺平，当成"libllama 的替代品"直接上生产要慎重，当成学习现代 Zig 写 GPU kernel 的样本则很值。

### 2. QwenLM/qwen-code — 终端 Agent 三巨头补齐第三位
29,810 星、Apache-2.0、昨天还在推送，qwen-code 的增速（+151）已经不像新项目，更像稳态产品。它的价值不在"又一个 Claude Code 克隆"，而在于**成本结构**：Qwen 系列模型的单价让"终端 agent 跑一整天"从奢侈品变成日常开销，配合 2,220 个 open issues 更像一份"社区在深度使用"的证据而非失控。本 catalog 里 Claude Code、OpenCode、Gemini CLI 早已在列，今天补上 qwen-code，四家对照看份额变化才有意义。唯一要留意的是文档站挂在 github.io 上，企业内网部署前先确认离线文档来源。

### 3. ggml-org/llama.cpp — 13 万星的老将今天还在涨 176
这不是"新项目"，是**压舱石**。每次 Trending 上出现的推理新秀（Zig 的 TensorFold、C 的 colibri、Python 的 FreeToken）最后都要拿 llama.cpp 当基线，它自己则靠新模型 Day-0 GGUF 支持持续吸量。今天这个 +176 与其说是它自己火了，不如说是"本地推理"这条赛道整体在升温的信号。想评估任何新推理引擎值不值得迁移，最省事的办法就是拿同一个量化模型在 llama.cpp 上跑一遍当分母——这条经验今天依然有效。
