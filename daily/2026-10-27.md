### 🥇 NVIDIA/SkillSpector —— skill 供应链安全正式成为「发布前置流程」

2.2 万星、Apache-2.0，NVIDIA 官方下场。真正的看点不在扫描器本身，而在它**被放进了发布链路**：SkillSpector 是 [NVIDIA Verified Skills 管线](https://docs.nvidia.com/skills/) 的第一步——扫描 → 评估 → **签名** → 发布进 NVIDIA skills catalog。换句话说，通过扫描的 skill 会拿到一个由大厂背书的签名，这跟 npm 的 provenance 机制是同一个逻辑，只是对象换成了 skill。

最扎眼的数字来自官方 README：**31,132 个 skill 的研究样本中，26.1% 含漏洞、5.2% 疑似恶意**。这个比例比当年 npm 生态的污染率还高——原因也很直白：skill 是**带隐式信任**安装的，Claude Code / Codex / Gemini CLI 加载它时不要求逐条确认，用户甚至不知道 skill 改写了什么系统提示。

技术上有三个设计值得抄：
1. **多格式输入**：git 仓库、URL、zip、目录、单文件都能扫——覆盖了 skill 的全部真实分发形态。
2. **71 个模式 / 17 个类别**：prompt injection、data exfiltration、privilege escalation、supply chain、excessive agency、system prompt leakage、memory poisoning、tool misuse、rogue agent、anti-refusal、trigger abuse……**「excessive agency」（过度授权）和「memory poisoning」（记忆投毒）是别的工具普遍漏掉的两类**，而这两类恰恰最贴近 skill 的实际攻击面。
3. **fail-closed 资源上限**：bundle、parser、嵌套产物、ledger、finding 都有硬性天花板，防止恶意 skill 用「资源耗尽」或「分析器递归」来自我规避。
4. **Pi / OpenCode 扩展**：可以在 agent 会话内部直接扫，而不是只能跑 CLI 门禁。

⚠️ 关注理由：1,937 fork / 8.7% fork 率在安全类项目里偏高（说明大量人是拿去接入自己 CI 而非读源码）；最后推送 2026-10-23，还有 175 open issues 相对 2.2 万星很健康。**注意它只解决「skill 本身恶意」，不解决「skill 描述的功能本身就是危险能力」**——后者是授权问题，得靠 OpenShell 那类运行时沙箱。

### 🥈 alchaincyf/huashu-design —— 「六个候选挑三个」是把设计不确定性显式化的关键设计

今日涨幅第一（+251），2.67 万星，MIT，**只有 6 个 open issues**——对 2.6 万星的项目来说这个数字低得反常（0.02%），说明作者要么把问题挡在门外，要么根本不用 issue 追踪。

3.0 的核心不是「AI 会做设计」，而是**把设计最不可控的那一步显式交给人**：
1. **六张缩略图 → 挑三个方向 → 才做真稿**。这是「先探索、后收敛」的工作流固化成 skill：以前设计师在 mood board 阶段纠结，现在这一步被压缩成一次选择。对比一下今天同时收录的 SkillSpector——一个项目在给 skill 装护栏，另一个项目在给 skill 装方法论，**skill 正在从「提示词片段」进化成「有 SOP 的专业角色」**。
2. **84 种带样张的风格库**（3.0 新增 App、中文、东亚三个分区）。每种风格配样张是个聪明设计：风格库最难的是「名字对不上效果」，直接给图就解决了对齐问题。
3. **设计体检只量事实**——不给「你做得不够好」这种主观评价，只给可测量的结论。这跟 2026-10-26 收录的 cloudflare/security-audit-skill 是同一种价值观：**可验证 > 听起来专业**。
4. **外观账本**：记住你做过什么样子，避免下一个项目长成一个样。这是把「风格一致性」从 prompt 里的形容词变成可累积的资产。

⚠️ 关注理由：README 里每一页设计都是它自己做的（不是 Figma、不是 AE），这是最好的 dogfooding 证据；2026-05-14 从「个人免费/商用需授权」转成 MIT 全开源，作者让利换生态。仓库主语言是 HTML 而非 Python/TS，说明它更像**方法论 + 模板资产**而非代码库——也意味着版本迭代的护栏比常规软件弱，抄之前先看 LICENSE 与素材授权。

1,475 星、12.5% fork 率（相对小盘项目偏高）、**202 个 open issues 对 1,475 星（13.7%）**——早期项目的真实反馈通道，别被星数迷惑。

1. **多 Agent 后端统一**：Codex App Server 与 Claude Code 原生接入，Grok CLI / OpenCode / Gemini / Cursor CLI / Cline CLI 走 ACP——**ACP 正在成为「换模型换 Agent」的通用插槽**，这一点比它自己实现的任何功能都更有行业意义。

1. **Skill 供应链正在补上「npm audit 时刻」，而且是同一天发生的两件事。** SkillSpector 给出 26.1% 漏洞率 / 5.2% 恶意率的硬数字，并把扫描-签名做进发布管线；同一天，huashu-design 把 skill 从「提示词片段」升级成带 SOP、带风格库、带体检、带外观账本的**专业角色**。两件事的方向完全相反：一边在给 skill 装刹车，一边在给 skill 装方向盘。**这说明生态已经进入「规模化」阶段——数量涨到值得被供应链攻击，质量也涨到值得被方法论沉淀。** 接下来真正稀缺的不是 skill 的数量，而是**可签名的 skill**。

2. **「Agent 宿主层」赛道的分歧点浮出水面：权限策略。** 今天 openbot 以 `danger-full-access` + `approvalPolicy: never` 上线，README 里自己写下了 WARNING；而同一周已在库的 NVIDIA/OpenShell 走的是完全相反的路线——内核级强制策略、凭据隔离、**形式化验证策略变更**。这两个项目放在一起看，几乎是 2026 年 Agent 工程的分水岭宣言：**Agent 有了操作系统级的「身体」之后，第一个要解决的不是能力，是「它拿到权限之后会做什么」。** 目前的市场是「先给权限再补安全」的 openbot 路线占上风（因为好用），但合规场景迟早只认 OpenShell 那一侧。

3. **成熟开源项目的「agentic 化」正在成为第二增长曲线。** Postiz 立项于 2023-07，三年后 3.8 万星仍在 +188/日——它没换赛道，只是把「社交媒体排期」重新包装成 agentic 工作流（Public API + NodeJS SDK + n8n 节点 + Make.com 集成，让 Agent 能调它）。同样地，huashu-design 的输出是 PPTX / App 原型 / 动画——**交付物而不是建议**。趋势很清楚：2026 年的价值锚点已经从「AI 能做」移到「**AI 能交付可直接使用的东西**」，谁能把产出物做到「不返工就能用」，谁就吃到下一波增长。
