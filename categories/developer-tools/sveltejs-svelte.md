# sveltejs/svelte

> 仓库：https://github.com/sveltejs/svelte · ⭐ 88,992（2026-11-17 API 实测） · JavaScript · License: MIT

**一句话：** web development for the rest of us —— 编译期框架的代表作，把响应式在构建时编译掉，运行时几乎零框架开销；2016 年立项至今仍是前端三大派系之一。

## 核心能力
- **编译时响应式**：没有虚拟 DOM，状态变更直接编译成精确的 DOM 更新
- **Svelte 5 Runes 体系**：$state / $derived / $effect 显式声明响应式，取代隐式魔法
- **单文件组件**：.svelte 里 style / script / markup 一体，学习曲线在三大框架里最低
- **SvelteKit 全栈**：路由 / SSR / 表单 action / 适配器部署（配套仓库）
- **极小的产出体积**：适合嵌入式、低带宽、移动端优先
- **MIT**：商用无顾虑

## 适用场景
- 追求极致包体积 / 首屏性能的 C 端产品
- 中小团队想要"少写样板"的组件化开发
- 嵌入式 UI、仪表盘、低配设备前端
- 想给 AI 生成前端找一个"输出体积可控、语法简单"的目标框架

## 为什么值得关注
- **它是"框架要不要在运行时存在"这个问题的长期答案之一**：十年了，编译期路线一直有稳定拥趸，Svelte 5 的 Runes 又把"隐式魔法"这个最大抱怨正面解决掉。
- **语法简洁度对 AI 生成代码极其友好**：单文件组件 + 少样板 = 模型出错面更小，这几年不少 agent 前端生成流程默认选 Svelte 不是没理由。
- **88.9K 星的常青位置**：今天 +115 属于正常的日常热度，不是拐点信号——它早已越过"要不要选它"的阶段，问题只剩"你的团队熟不熟"。
- ⚠️ 关注理由：**1,313 个 open issues 是今天清单里最多的**，说明 issue 吞吐压力大（很多是 RFC/feature 讨论而不是 bug）；招人市场上 Svelte 候选人池远小于 React，团队规模大时这是真实成本。
